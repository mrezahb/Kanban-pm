# طرح پایگاه داده

این سند تصمیم‌های طراحی SQLite برای MVP را ثبت می‌کند. طرح ساختاریافته در [database-schema.json](./database-schema.json) قرار دارد. این مرحله فقط طراحی است؛ ساخت پایگاه داده و API تا تأیید طرح انجام نمی‌شود.

## مدل و محدودیت‌ها

- `users` نام کاربری یکتا و فقط hash گذرواژه را نگه می‌دارد. کاربر MVP با نام `user` از اعتبار ثابت MVP ساخته می‌شود؛ گذرواژهٔ خام در SQLite ذخیره نمی‌شود.
- `boards.user_id` یکتا است؛ بنابراین هر کاربر حداکثر یک برد دارد. مدل‌های کاربر و برد از ابتدا چندکاربره‌اند.
- برد با پنج ستون فعلی رابط آغاز می‌شود. ستون‌ها قابل تغییرنام و افزودن‌اند؛ `position` ترتیب آن‌ها را نگه می‌دارد.
- کارت به ستون تعلق دارد و `position` ترتیبش را در همان ستون مشخص می‌کند. شناسه‌های UUID متنی، ترتیب صفرمبنا، و قیدهای یکتایی، رکوردها و جایگاه تکراری در یک برد یا ستون را محدود می‌کنند.
- کلیدهای خارجی با `ON DELETE CASCADE` داده‌های وابسته را هنگام حذف مالک، برد یا ستون پاک می‌کنند. SQLite باید با فعال‌بودن foreign keys باز شود.
- جابه‌جایی و مرتب‌سازی باید در تراکنش انجام شود و موقعیت‌ها را بدون برخورد با قید یکتایی بازشماری کند.

## نشست و زمان‌ها

- مقدار خام توکن نشست فقط به کاربر داده می‌شود؛ SQLite تنها hash توکن را با قید یکتایی نگه می‌دارد.
- زمان‌ها به‌شکل متن ISO 8601 در UTC ذخیره می‌شوند. `expires_at` هفت روز پس از `created_at` تعیین می‌شود و نشست با مقدار `revoked_at` باطل می‌شود. اعتبارسنجی نشست باید هم انقضا و هم ابطال را بررسی کند.
- حذف کاربر، نشست‌های او را نیز حذف می‌کند؛ نشست منقضی‌شده را می‌توان با شاخص کاربر و زمان انقضا برای پاک‌سازی پیدا کرد.

## وضعیت تأیید

امکان افزودن ستون به‌عنوان تصمیم محصول تأیید شده است. کاربر طرح را برای مبنای مرحلهٔ ۵ تأیید کرده است. پیاده‌سازی پایگاه داده هنوز انجام نشده است.
